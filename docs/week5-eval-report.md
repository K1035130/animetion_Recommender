## 1. ✅ 跨语言惩罚：翻译前后的真 A/B

`uv run --group etl python scripts/eval_crosslang.py`

### 结论

**当初 −27.7 pp 的跨语言惩罚是真的，而语料转中文把它完全消除了。**

| | 这 3,809 部在 top-50 的占比 | 相对基准 35.06% |
|---|---|---|
| **翻译前**（日文简介） | 6.60% | **−28.46 pp** |
| **翻译后**（中文简介） | 35.40% | **+0.34 pp** |
| **净改善** | | **+28.80 pp** |

### 为什么这个实验比"前后各测一个数"强

不是重新测一遍，而是**把库里被翻译过的 3,809 部作品的向量换回翻译前那份日文文本的向量**
——译文缓存存着日文原文（`src`），而 `embed_cache` 里还留着**翻译之前**编码它们时的向量。

```
同一批查询 · 同一个模型 · 同一批作品 · 同一套指标
                唯一的变量 = 语料语言
```

「前后各测一个数」的做法会把**查询集变化、模型抖动、库内容变化**三个因素混在一起，
这里三者全部被钉死。

📌 **而且它独立复现了原始测量**：本次用的是**另外 10 条查询**、另一套方法，
翻译前测出 **−28.46 pp**，与 2026-08-16 那次的 **−27.7 pp** 收敛到 0.8 pp 以内。
两次独立测量互证 ⇒ 这个结论可以放心写进报告。

逐查询看更直观（满分 50，无惩罚时期望 17.5）：

| 查询 | 翻译前 | 翻译后 |
|---|---|---|
| 主角很强但很低调的番 | **0** | 13 |
| 科幻题材的动画 | 1 | 23 |
| 悬疑推理 | **0** | 19 |
| 关于组乐队的动画 | 4 | 27 |
| 催泪的恋爱故事 | 3 | 22 |

⚠️ 「主角很强但很低调」「悬疑推理」在翻译前是 **0/50** —— 与原始测量记的
「最极端的三条都是 1/50」吻合。

### ⚠️ 直接复测原指标已经**没有统计功效**，别用它下结论

| | 值 |
|---|---|
| 全库日文简介基准率 | **0.36%**（39 / 10,864） |
| 10 条查询 top-50 里的占比 | 0.00%（0 / 500） |
| 偏差 | −0.36 pp |
| **零假设下的期望命中数** | **1.8 条** |

期望命中不到 2 条，此时"偏差 −0.36 pp"**不具备判别力** ——
它既不能证明惩罚消失，也不能证明还在。
📌 **结论只能由 A/B 那半边承担**，这也是为什么必须做 A/B 而不是简单复测。
（同一条教训：`EMB_TOL` 当初拿 12 组小样本定阈值，扩样后余量只剩 1.3 倍。）

### 已知局限

- 查询集是本次新定的 10 条（**原始那 8 条没有被记录**，所以那次测量严格来说不可精确复现）。
  ⇒ 从这次起查询集写死在 `scripts/eval_crosslang.py` 里，进版本库。
- 缓存未命中的行保持现状向量不变 —— 这是**保守方向**，会低估差异不会夸大。
  本次实际未命中 0 条。
- 相关性判据是「作品简介是不是日文」，不是「该作品是否真的相关」——
  这个指标测的是**召回机会的公平性**，不是排序质量。

## 2. ✅ HyDE 正式对照：**结论是默认关，且 RRF 也不值得**

`uv run --group etl python scripts/eval_hyde.py`

20 条查询 · 候选池 9,478 部 · 每条查询一次 Qwen3-14B 调用。

| 腿 | P@10 | NDCG@10 | 相对 base | 95% CI（NDCG 差） | 胜/负 | 符号检验 |
|---|---|---|---|---|---|---|
| **base**（原查询直接编码） | **0.640** | **0.638** | — | — | — | — |
| hyde_q（HyDE→embed_query） | 0.465 | 0.471 | −17.5 pp | **[−0.289, −0.050]** | 4/16 | **p=0.012** |
| hyde_d（HyDE→embed_documents） | 0.455 | 0.469 | −18.5 pp | **[−0.272, −0.062]** | 3/17 | **p=0.003** |
| rrf(base, hyde_q) | 0.585 | 0.594 | −5.5 pp | [−0.120, **+0.034**] | 8/11 | p=0.65 |

**三条结论：**

1. **HyDE 显著有害** —— 两种编码方式的 95% 置信区间都不含 0，符号检验也显著。
   ⇒ **G.5d 的"默认关"从三条查询的印象升级成了有统计支撑的结论。**
2. **RRF 融合救不回来，也不值得做** —— 它的置信区间**含 0**（p=0.65），
   即"与 base 无显著差异"。⚠️ 但它要多付一次 LLM 调用（1–9 秒）和一次编码。
   ⇒ **付出确定的延迟，换一个统计上为零的收益。不做。**
   📌 这一条修正了 G.5c 的建议（当时提议用 RRF 融合两条腿把两边的好处都拿到）。
3. **`embed_query` vs `embed_documents` 之争可以结案了** —— 0.471 vs 0.469，
   差异远小于两者与 base 的差距。`src/llm.py` 的 `hyde()` docstring 里挂着的
   那个"未决开关"**不重要**，因为整条腿都不该开。

### 📌 HyDE 不是全无用处 —— 它赢的那 4 条有规律

| 查询 | base | hyde_q | 差 |
|---|---|---|---|
| 发生在学校社团里的故事 | 0.37 | **0.82** | +0.45 |
| 以古代历史为背景 | 0.31 | 0.36 | +0.05 |
| 变身战斗的魔法少女 | 0.54 | 0.67 | +0.13 |
| 充满斗志、永不放弃 | 0.28 | 0.35 | +0.07 |

而它输得最惨的是 **演艺圈里成长的偶像团体（1.00 → 0.15）**、
**战场上的军队与士兵（0.39 → 0.07）**、**体育竞技与社团训练（0.71 → 0.14）**。

⇒ 与 G.5c 观察到的规律一致：**查询措辞本身已经贴近简介文体时，
HyDE 生成的泛化套路简介会把区分性信号稀释掉**；只有查询很抽象时它才补上文体鸿沟。
而语料转中文之后，"基线本来就够好"的情形占了绝大多数。

### 🔑 自动标注是怎么做到的（这一节的方法本身值得写进报告）

HyDE 对照一直做不大，卡在**没有相关性标注**。这次的解法：

> **`anime_profile.vec` 只编码 `summary`，从没见过 `tags`**（A.10 的纪律：
> 拼 tags 会让 embedding 这条 baseline 秘密变成 tag+embedding 混合体）。
> ⇒ **tag 是一份天然的 held-out 相关性标签**，用它评 summary-embedding 检索
> 不存在自我印证。

📌 **A.10 当初是为了保住第 5 周 ablation 的独立性才定的纪律，
现在它意外地变成了评测资产** —— 这类"纪律带来的红利"值得在报告里点出来。

### 已知局限

- **tag 覆盖不全** ⇒ P@10 的绝对值被系统性低估（一部讲美食的番可能没人打「美食」）。
  ⚠️ 只能做腿与腿之间的比较，**不要把 0.640 当成"我们的检索准确率"对外报**。
- 20 条查询都是"描述性找番"（流程 B 路径①），**不覆盖点名类查询**（那是路径②/alias 的活）。
- 相关性是二元的，没有分级；NDCG 的 IDCG 取满（每个 tag 的相关作品都远超 10 部）。

## 3. ✅ 点名类检索：自动标注 150 题

`uv run --group etl python scripts/eval_retrieval_named.py --n 150`

从 `alias` × `plot_chunk` 自动抽 150 个角色（所属作品 `fav_done ≥ 2,000`），
问「X 是谁？」，**标准答案客观可判**：`character_id = X` 的那几条 chunk。
每题只 rerank 一次，参数扫描靠离线模拟（cross-encoder 的分是 (query,doc) 对的属性，与批次无关）。

### 3.1 解析层：11.3% 的点名题在进入检索之前就失败了

| G.4 状态 | 占比 | 含义 |
|---|---|---|
| `ok` 且作用域正确 | **88.7%** | 可进入检索 |
| `ambiguous` | 8.0% | 名字撞多部作品，走反问 —— **设计如此，不算错** |
| `ok` 但**作用域错了** | **3.3%** | 🚨 解析到了**别的作品**，静默走错 |

📌 那 3.3% 是 G.4 状态② 想防而没防住的情形（与「`海贼王%` 实际匹配到《海贼王女》」同类）。
⇒ **报告里「检索命中率」必须写明分母是 88.7% 那部分**，否则会把解析层的失败算到检索头上。

### 3.2 🔑 alias 直取的净贡献：100% vs 28.6%

| 配置 | 命中率（133 题） |
|---|---|
| **直取=开（线上形态）** | **100.0%** |
| 直取=关（消融） | **28.6%** |

**G.5g 那句「alias 是确定性的解法，不是可选优化」现在有了数字。**
⚠️ 消融的正确做法是**只丢掉「仅靠直取才进来」的那些**，
留在召回池里的仍按普通召回项处理 —— 我第一版直接把 pinned 删掉，
得到"0.0%"这个假结果（合并时本人 chunk 被去重成了 pinned 那一份副本）。
📌 与 I.8 ② 同一条教训：**测试构造得不对，绿灯红灯都毫无意义。**

### 3.3 🚨 `MIN_SCORE=0.05` 比想象中激进：在纯召回路径上吃掉 22.5 pp

左列 = 线上形态（直取开），右列 = 关掉直取后**纯召回+rerank**的判别力：

| MIN_SCORE | 直取=开 | 直取=关 |
|---|---|---|
| 0.00 | 100.0% | **51.1%** |
| 0.01 | 100.0% | 42.1% |
| **0.05（现值）** | 100.0% | **28.6%** |
| 0.10 | 100.0% | 27.1% |
| 0.40 | 100.0% | 26.3% |

**把地板从 0.05 降到 0，纯召回路径的命中率从 28.6% 涨到 51.1%** ——
也就是说 **22.5% 的标准答案 chunk 的 rerank 分落在 (0, 0.05) 区间**，被地板砍掉了。

⚠️ **但这不构成"立刻改 0.05"的结论**，两个理由：
- **线上不受影响**（左列恒为 100%）：pinned 豁免地板，正是 I.2 ① 的设计意图。
  ⇒ 现有配置在点名类问题上是安全的，这条测量反而**验证了 PIN_RESERVE 的必要性**。
- ⚠️ **本测是描述性路径的 proxy，不是描述性路径本身**：题面「X 是谁」含角色名，
  而 **93.3% 的角色 chunk 正文里没有角色自己的名字**（F.7b ①）——
  所以这类题的向量/rerank 分**天然偏低**，右列会**低估**真实描述性问题的表现。

⇒ **待 B.1 的人工题库出来再定**。若那批也显示地板砍掉真答案，可考虑
**改成相对地板**（如 ≥ top1 分数的某个比例）：I.2 ② 那个原始案例
（0.873 / 0.671 | 0.060 / 0.032…）用「≥5% of top1 = 0.044」同样能砍对，
而不会误伤"整体分数都不高但确实相关"的那类。

## 4. ✅ 可回答率（B.1）：60 题人工打分完成

**一句话结论：瓶颈在检索与语料，不在生成。**
资料里有答案时模型 **93.8%** 答对；而资料里有答案的只有 **30.8%**。

| 指标 | 值 |
|---|---|
| **检索命中**（答案在资料里） | **16 / 52 = 30.8%** |
| 端到端答对 | 23 / 52 = 44.2% |
| ├ **命中时答对（生成质量）** | **15 / 16 = 93.8%** |
| └ 未命中时正确拒答 | 28 / 36 = 77.8% |
| 🚨 未命中却给了答案 | 8 / 36 = 22.2% |

⚠️ **「端到端答对」比「检索命中」还高，这个反常必须解释**：
23 − 15 = **8 道是在检索没命中的情况下答对的** —— 也就是那 8 条「未命中却给了答案」
**内容全部被判为正确**。⇒ 模型在用训练记忆作答，而且答对了。
🚨 **这是最危险的一格**：没有出处、不受剧透门控约束、绕过整条 RAG 链路，
而**因为答对了，用户完全看不出来**。G.4 状态③ 想防的就是它。

⚠️ **口径提醒**：5 道 `ambiguous`（反问）里有 4 道被判 `answer: y`（反问本身是好行为）。
它们计进了「端到端答对」但并没有给出答案 ⇒ 剔除后是 **19/47 = 40.4%**。
📌 下一轮应给反问单列一个状态，别混进答对率。

### 4.2 🚨 「片头片尾」8/8 失败 —— **100% 是 `MIN_SCORE` 地板造成的**

Kevin 的 note 说「语料里应该有但没成功找到」。逐条 trace 后确认**他是对的**，

**E.4 早就写过「歌名是关键词查找，走 BM25 更准」**，这是同一现象在 rerank 侧的表现。
⚠️ 而整条查询的分数分布本来就低（top1 只有 0.275 / 0.054）⇒
**绝对地板在"整体分数都低"的查询上是错的判据**。

**实测过的两个修法**（都还没实现）：

| 修法 | 效果 |
|---|---|
| 相对地板（≥ top1 的 5% / 2%） | 5 题里救回 2 / 3 —— **部分有效**。∀高达 top1=0.543 时 5% 仍高于 0.0032 |
| **按类型豁免**：问句含「片头/片尾/OP/ED/主题曲」且该 chunk 是 songs 层第 1 → 豁免地板 | 与 `PIN_RESERVE` 同一思路（保「在不在」不保「排第几」），**用规则而不是调阈值**（第 15 节原则 2） |

### 打分表的两处刻意设计

**① 「检索命中」的填空排在模型回答之前**，模型回答折进 `<details>` 里。
这是**物理上强制 G.5f 那条纪律**：先判资料里有没有答案，再看模型答得对不对。
🚨 反过来会系统性地**奖励幻觉、惩罚正确的拒答** —— 我在 G.5f 那轮就判错过一次
（把 Hunyuan 张冠李戴记成 ✅、把 Qwen3-14B 的正确拒答记成 ❌）。

**② 🚨 资料必须全文照登 —— 显示截断会系统性地制造假幻觉。**（2026-08-19 Kevin 发现）
初版给每条 chunk 设了 170 字的展示上限、超出补一个「…」。实测
**244 条里 104 条（43%）被截，共截掉 15,776 字**。而打分的第一问正是
「答案在不在资料里」：

```
【鲁道夫·冯·高登巴姆】全长 410 字，被截在第 170 字：
    「…宇宙历310年，把民主主义的银河…」
下一句正是答案：「联邦改为专制主义的银河帝国，自任皇帝」
```

⇒ 打分人会标 `retrieval: n`，而模型（看到的是全文）答对了 →
被记成 **「未命中却给了答案 = 幻觉」**。**指标会朝着最不该错的方向错。**
📌 **纪律：给打分人看的材料必须与模型看到的完全一致**，同 I.8 ②
「测试构造得不对，绿灯毫无意义」。已改为全文照登（表 133 KB → 175 KB），
只对 >1200 字留安全阀，且**明说还剩多少字**，不留含糊的省略号。

⚠️ **顺带澄清一个会误导打分的歧义**：库内 **1.53%（1,372/89,544）的 chunk
本来就以省略号收尾**（bangumi_char 942 + moegirl 430，多为简介留悬念，
如「…会听从村上的任何愿望……」）。⇒ 现在表里出现的「……」**一律是语料原文自带的**，
不代表后面还有内容没显示。这一条已写进打分表表头。

**③ 打分表自包含，不依赖 `data/interim/` 的原始 JSON。**
题型、状态全部从表里解析，`counted` 由 `MIX` 派生。
⚠️ 理由是**打分表在 `docs/` 会被提交，而 `data/interim/` 不入 git** ——
两者绑在一起的话，换机器后表还在、指标却算不出来了。
与「不入 git 的文件参与打分链路是定时炸弹」（B 节 `series_root.json`）同一条。
📌 已实测：把原始 JSON 改名藏起来，`score` 照常工作。

## 5. ✅ B.4 参数扫描：`MIN_SCORE` 结案，剥作品名否决（2026-08-20）

**一句话结论：A（地板）实现了，B（剥作品名）实测净收益为 0，不实现。**

复现：

```bash
uv run --group etl python scripts/eval_min_score.py pool --probe-rerank   # 重跑检索
uv run --group etl python scripts/eval_min_score.py sweep                 # 离线扫，免费
```

口径：题目复用 §4 那 60 题（`eval_answerability_raw.json`，逐题对应），
**55 题可用**（5 题 `ambiguous` 被 `resolve` 挡在检索之前 —— 题号 25/30/32/40/49，
与 §3.1「解析层 11.3% 失败」同一现象）。
不调 LLM —— 本节全部指标在**检索侧**，客观可判。

### 5.1 🔑 两条让扫描能离线做完的性质

**① `MIN_SCORE` 实际只控制一件事：`others` 的前缀取多长。**
`_apply_pin_reserve` 里 `others` 已按 rerank 分降序，
`[c for c in others if score >= floor][:room]` 恒等于取一个前缀。
⇒ **降低地板是纯增量的**，55/55 题实测验证。
🚨 由此**不用测就能断言**：降地板不可能让 §4 里已命中的题变成未命中 ——
**检索侧代价恒为零，全部代价在生成侧**（I.2 ② 的上下文稀释）。

**② rerank 分数有 ~1e-3 的噪声，这直接否掉了"把 0.05 调小"这条路。**

| 对照（12 文档 × 5 次重复） | 中位 | max |
|---|---|---|
| 同批重发（服务端连续批处理） | 0.00e+00 | **7.96e-04** |
| 跨批同文档（padding：批内补齐到最长序列） | 5.30e-04 | 6.10e-04 |

而 §4.2 里被砍掉的 songs chunk 得分是 **0.0032 ~ 0.0282** ——
噪声最高占最低分的 **25%**。⇒ **1e-3 量级的绝对地板在物理上就调不稳。**

🚨 **单次试验会给出相反的结论。** 首轮"同批重发"恰好返回 `0.000e+00`，
据此写下"reranker 对固定批次是确定的、3e-4 全是 padding"——
重复 5 次立刻翻案。**这与 A.7 那次一字不差**（原文：「第一次探测时前者
恰好返回 0.000e+00，那是碰巧不是确定」）。
⇒ **凡是"差异为零"的观测，必须重复若干次才能当成结论。**

### 5.2 ✅ A 地板：规则完胜调阈值（§4.2 结案）

客观判据：7 道 OP/ED 题，「最终集里有没有 songs chunk」。

| 判据 | songs 命中 | 上下文新增/题 |
|---|---|---|
| **绝对 0.05（原）** | **0/7** | — |
| 绝对 0.0 | 4/7 | +3.44 |
| 绝对 0.01 | 2/7 | +1.42 |
| 相对 top1×0.02 | 4/7 | +2.02 |
| 相对 top1×0.05 | 3/7 | +1.16 |
| **保底席位（已实现）** | **5/7** | **+0.09** |

⇒ **救回更多，代价小 38 倍。** 这是第 15 节原则 2「确定性门控 > 调参」
第一次拿到量化对照。
⚠️ 剩下 2 题（大闹天宫 / 西游记之大圣归来）**池子里根本没有 songs chunk** ——
语料覆盖问题，地板怎么改都救不回 ⇒ **在能修的 5 题上是 5/5**。

📌 **两次独立运行的稳定性本身也是证据**：规则那一行两次都是 5/7，
而阈值那几行在抖（`相对 top1×0.1` 从 0/7 变 1/7）—— 正是 5.1 ② 的噪声在起作用。

**实现**：`src/retrieve.py` 的 `SONGS_SEAT` / `songs_seat()`，

（豁免版仍按分数序取前缀，低分 chunk 照样被 `[:room]` 截掉）——
这是 I.2 ① 那条教训的原样复发，已由 `tests/test_retrieve.py` 5 项锁死。
端到端实测 4 道 OP/ED 题全部召回 songs chunk（0.0033 ~ 0.0274），
对照题「讲了什么故事」正确地不触发。

### 5.3 ❌ B 剥作品名：净收益 0，不实现（§4.3 否决）

判据：作用域内**最长的那条剧情章节**（叶子 section 匹配剧情/简介/故事…）
的层内名次，以及它有没有进 `QUOTA_SERIES=10`。

```
30 题可比：名次前进 13 · 不变 9 · 后退 8
进入配额：  救回 +3 · 掉出 −3 · 净 +0
```

§4.3 报的两个例子（一人之下、头脑特工队）**都是真的**，但它们是挑出来的。
掉出配额的三题是银河英雄传说 #6→外 · 魔法科高校 #2→外 · 在地下城 #10→外。

⚠️ **也做不成"大作用域才剥"这种条件规则**：最大的 8 个作用域恰好 4↑/4↓。

🚨 **顺带记一个方法学错误，它差点让这个无效改动通过。**
第一版挑目标 chunk 用的是 `min(cands, key=lr_strip)` ——
**按剥名后的名次挑目标**，等于"哪条在新方案里表现好就拿哪条来证明新方案好"。
那一版报出「净救回 **+4**」；改成与变体无关的判据（最长的那条）后立刻变成 **+0**。
⚠️ 与 I.8 ②「测试构造得不对，绿灯毫无意义」同族，
而这类偏差**只往有利方向偏**，最难被自己发现。

代码作为**可复测的负结果**留在 `scripts/eval_min_score.py`（不在 `src/`）——
阶段 06 抓角色页会大幅改写系列层语料，届时重跑 `pool` + `sweep` 即可复测。

### 7.3 🚨 脚本报的「幻觉 84.6%」是**量具问题**，不是系统退化

```
未命中却给了答案（幻觉）   基线 8/36 · 22.2%   →   v5 22/26 · 84.6%
路由类正确拒答            基线 2/8 · 25%      →   v5 0/8 · 0%
```

**这两个数不能按字面用。** 全表 `retrieval:n + answer:y` 共 **26 道**
（前五类 22 道 + 路由类 4 道），**已逐条读完原文，0 道是编造** ——
全部带边界声明，实质内容都能在资料里找到。

⚠️ **别把这个 26 和上面 `26/52` 那个 26 弄混**：后者是「前五类里未命中的题数」，
两者数值撞车纯属巧合（前五类 52 题里命中 26、未命中 26，而未命中的 26 道里
22 道给了答案、4 道拒答；另有路由类 4 道也是 `n+y`）。

根因是**判据定义于旧 prompt 时代**。08-23 那次 `ANSWER_SYSTEM` 改动
（「不要只说资料中没有就结束」+「已知剧情推进到」）的设计目的，
恰恰就是把拒答转成有据的部分回答 —— 逐题交叉可以看到它精确地发生了：

```
r:n→n  a:r→y    20 道   ← 拒答 → 有据的部分回答（**改动的目标行为**）
r:y→y  a:y→y    18 道
r:n→y  a:r→y     9 道   ← 检索也修好了
r:n→n  a:y→y     4 道
r:n→y  a:y→y     3 道
r:n→n  a:y→r     3 道
r:n→n  a:r→r     1 道
r:y→n  a:n→y     1 道   ← [38]，见 7.4
```

而脚本把「拒答」定义成 `answer: r`，于是：

- **路由类那 8 道其实都在拒答**，只是拒答里带了解释就被判成 `y`。
  [59] 佐贺偶像、[60] 心灵奇旅正确说明资料里没有原作者信息；
  [53] 地下城、[55] 青梅竹马正确说明资料里没有动画播出时间。
- 结局那批的形态是「资料里没有写到结局。已知剧情推进到：…」，
  正是 08-23 那节要的东西。

🚨 **⇒ 这与「评测口径 bug」（打分表看不见 `aux`）是同一族的问题：
不是系统变差了，是量具没跟上系统。** 而且两次都只在**人去读原文**时才暴露 ——
指标本身看起来完全正常，只是含义已经漂了。

⬜ **建议改判据**（会改变指标定义，未实施，等拍板）：
「幻觉」应判**回答里有没有资料支持不了的实质断言**，而不是「未命中却给了答案」；
「正确拒答」应把带解释的拒答算进去，而不是只认 `answer: r`。

### 7.4 唯一退的一道 [38]：**同一批资料上的打分翻转**

`[38] 角色关系 · 龟田元气和白田大牙是什么关系？` 基线 `r=y a=n` → v5 `r=n a=y`。

**两轮的资料几乎逐字相同**：同 4 条 chunk、同顺序、分数只差 0.001，
唯一差别是那条 songs chunk 多了 08-22 解析修复补上的「片头曲(OP)：」前缀
（与本题无关）。两条角色 chunk 都只写到「喜欢牡丹」。

⇒ **不是语料退化，是两轮对同一份证据的判断不同**
（基线判「喜欢牡丹算是关系」、本轮判「未明确说明直接关系」）。
📌 **所以「角色关系 20% → 10%」这个退化只有 1 道，且落在评分主观性上，
不要据此改检索层。** 角色关系类真正的问题仍是 §4.5 记的那条：
**语料里普遍没有"两个角色之间"的关系陈述**，10 道里 9 道命中不了。

### 7.6 已知局限

1. **生成侧的三个数（92.3% / 100% / 84.6%）跨了两版 prompt，不可与基线并排。**
