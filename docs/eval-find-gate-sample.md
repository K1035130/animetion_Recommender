# 找番门控（find_gate）抽样打分表

> 2026-08-24，流程 B 找番刚上线时的第一轮人工检查。**10 题，全部真实调用
> `POST /api/ask` 得到**，不是编的。目的：`llm.find_gate()` 该不该保留这个设计，
> 还是要调整 prompt / 措辞 —— 打完这十题再决定要不要补 `tests/test_find.py`。

> **背景**：`resolve()` 完全没认出任何作品/角色时（`state=unknown`），
> 系统会先调一次 LLM 判断这句话「值不值得展示语义找番结果」——
> 判"是"就展示 `anime_profile.vec` 语义检索的 top-8（措辞谦虚，不敢说"找到了"）；
> 判"否"就返回套话「描述有些模糊不清，能再具体一点吗？」。
> 起因是语义检索对任何输入都会返回一个 top-8（cos 排序不存在"零结果"），
> 手调一个余弦地板去区分"在题/离题"被实测证明不可靠（离题查询「今天天气怎么样」
> top1=0.540，比不少真实找番查询还高），所以改成让 LLM 判一次。

> **两问打分规则**：
>
> **第一问 `gate:`** —— 这道题该不该展示找番结果，**你的判断**是什么？
>   `y` = 应该展示（这是一段合理的找番描述） / `n` = 不该展示（太模糊/离题/无意义）
>   ⚠️ 只看你自己的直觉，不看系统实际判了什么——这是在校验 gate 判得对不对，
>      不是在确认系统的判断。
>
> **第二问 `result:`** —— 系统实际展示给用户的内容，**你觉得合适吗？**
>   `y` 合适 / `n` 不合适，并在 `note:` 写一句为什么
>   （常见的"不合适"：gate 判断本身错了；gate 判对了但找回来的番不沾边；
>   套话文案生硬）

**指纹**：`route="voice"` 强制走声优分支——**这题是回归保护，不测 gate 准不准**
